# IRS 迁移角色与路由契约 (M1 草案)

## 1. 架构原则与职责边界
- **单一人类授权源**：所有执行源于明确范围的人类授权；文件内状态标记仅为投影，不构成授权源。最新业务停止策略 `USER-POLICY-PAUSE-AFTER-B04-20261002-001` 仅作用于业务域，不撤销已授权之迁移建设 `USER-MIGRATION-M1-START-20261002`。
- **最小权限与边界隔离**：无跨阶段隐式授权；各角色仅在受控边界内流转请求与证据。
- **历史兼容与状态事实**：旧角色 01..05 历史记录受控冻结保留；实际新角色会话与 Thread ID 尚未创建。

## 2. 核心角色定义
- **总览与需求接入角色 (New00 Intake/Overview)**：读取派生状态并路由请求，承接迁移任务输入与状态映射；不持有状态写权，不持有发布审批权，不执行业务代码修改。
- **阶段审批角色 (Stage Approval)**：依据人类有效授权与完整证据链执行阶段门禁签署；持有发布终审权；不代替验收角色产生技术测试。
- **版本验收角色 (Version Acceptance)**：独立执行规格对比、自动化验证及真实截图视觉检验，产出包含哈希的技术与视觉验收结论；无权越权批准放行。
- **即时/独立交付角色 (Ad-hoc Delivery)**：负责承接独立的额外 HTML、报告生成及专项交付任务，任务完成即关闭上下文会话周期（completion closes context）；同时负责经审批放行后的交付物归档与外部仓库同步对接。
- **实现工程师 (Gemini Implementation Engineer)**：唯一代码与文档实现方，产出补丁/方案候选；执行文本先经独立审查再受控应用；无自主写执行权限。
- **架构与任务审查方 (GPT Reviewer)**：负责定义任务契约、接口规范与独立交叉审查；每次独立判定仅基于当次相关紧凑上下文，不注入或维持全量历史与 Gemini 工具调用历史。
- **宿主执行器 (Host Runner)**：仅负责本地受控事件持久化与等待状态转移，无 LLM 轮询，不作主观正确性裁决。

## 3. 消息流转与路由矩阵
1. **迁移任务接入**：人类指令/迁移授权 -> New00 (读取派生状态、解析登记与路由分发) -> GPT (生成任务契约)。
2. **实现与审查**：GPT 契约 -> Gemini (生成文本候选) -> GPT (基于紧凑上下文独立审查签署) -> 宿主 (受控应用)。
3. **验收与放行**：受控部署 -> 验收角色 (技术+真实截图核验，产出证据哈希) -> 审批角色 (比对人类授权与范围，签发放行决策) -> 即时交付角色 (独立专项交付或打包同步，完成后关闭上下文)。

## 4. 视觉核验与五大绑定准则
- **双轨视觉定义**：Agent 视觉审查指对真实捕获截图的工具化/模型校验；人类视觉核验指用户亲自核实。严禁用模拟日志替代真实截图。
- **五大绑定凭证准则**：
  1. 发布审批必须绑定 `request_id + git_commit/tree + evidence_hash + scope`；
  2. 环境准入绑定目标环境标识与操作时限；
  3. 预 Git 文本提议绑定内容哈希；
  4. 变更候选自动作废受影响旧提议，历史记录仅追加保留；
  5. 视觉核验必须绑定真实捕获截图文件路径与内容指纹，拒绝模拟伪造。
