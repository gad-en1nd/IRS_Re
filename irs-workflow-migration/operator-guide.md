## 2. 授权范围与操作边界
- **常规迁移推进**：操作员已有授权覆盖既定迁移流程与经评审的文件写入，在此授权范围内可正常推进，不要求每步重复申请人工审批。
- **必须人工明确授权的情形**：仅超出既定迁移范围的动作、新的高风险操作、恢复业务运行等，必须获得操作员明确指令。GPT 绝不伪造人工授权。
- **交付承诺底线**：不承诺系统自动切流、不承诺成本节约、不承诺全量工程即刻可用。

## 3. 权威状态源与事实基准
- **唯一权威**：不可变的初始快照 + 经核准的事件账本（`events.jsonl`）+ 受保护的出处记录；`state.json` 与状态查询均为衍生视图，非独立真相源；决策审计记录不具备额外状态写入权。
- **GitHub 状态事实**：
  - 历史交接快照中的 403 属不可变的历史快照记录，后续已通过实际收据确认恢复。
  - `state.github_status` 仅为初始快照标签，不执行在线拉取刷新。
  - 最新权威事实以 `acceptance/github-receipts.json` 为准，收据记录已确认的节点提交；最终节点提交同时见 GitHub 历史，避免收据引用自身提交形成循环。

## 4. 运行器命令规范
所有执行命令均需指定根目录：
- 初始化：`python runner.py --root <项目路径> init`
- 查看状态：`python runner.py --root <项目路径> status`
  - 仅输出当前状态与事件计数，不进行远程查询，不聚合 GitHub 收据。
- 异常恢复：`python runner.py --root <项目路径> recover`
- 事件入账：`python runner.py --root <项目路径> ingest <事件文件.json>`（仅接收单一文件参数）。

## 6. 上下文与任务流转规则
- **有界任务流转**：模型间流转必须使用有界独立任务包，严禁整段倾倒全量会话历史。
- **上下文滚动**：历史体积过大时，基于当前状态基准与不可变任务引用重新拉起新轮次，严禁直接复制旧 00 的完整历史。
- **查看方式**：操作员在概览入口查看进度汇总，在验收入口查看关键节点，无需逐一访问每个会话入口。
