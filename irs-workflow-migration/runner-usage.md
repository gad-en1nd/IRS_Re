# Runner 使用说明与操作规范

## 1. 基础命令行操作
Runner 仅支持标准 CLI 交互，无后台常驻进程：
```bash
python runner.py --root PROJECT init
python runner.py --root PROJECT status
python runner.py --root PROJECT recover
python runner.py --root PROJECT ingest EVENT.json
```

## 2. C07 核心架构特性
- 零外部依赖：核心完全不包含 LLM 调用、网络请求或子进程派生。
- 纯事件驱动：空闲状态下代码调用次数恒为 0，仅在显式命令行触发时执行。

## 3. 验收测试套件
- 规格定义 23 个单元测试用例，位于 acceptance 目录。
- 执行验证命令：
  `python -m unittest discover -s acceptance -p test_runner.py`
- 规则：保留并忽略临时 scratch 产物；禁止声明测试已在当前环境执行通过。

## 4. 私有可信源与数据溯源
- 私有注册表必须由真实人类操作者提供宿主种子（包含真实引用与证据哈希），生成初始不可变快照。
- 仅执行代码仓库克隆无法直接运行，必须先完成合法私有源溯源注入。
- 严禁使用模型生成的任何虚构源溯源数据。

## 5. 作用域与状态机约束
- 作用域严格限定于 M1 迁移；当前业务按最新策略保持暂停（paused）状态，无 resume 事件。
- 派生状态：state 与 status 仅由事件日志严格派生，状态文件本身不是最终事实权威。
- 不可变证据：证据路径严格规范且不可变；篡改历史决策引用的证据字节将导致重放失效，必须使用版本化工件引用。

## 6. 幂等性与冲突处理
- 重复执行 `init`、传入重复事件或执行 `recover` 可用于恢复陈旧视图。
- 严格拒绝冲突事件与审计破坏行为；校验失败的预期事件决不追加至日志。

## 7. GPT 审核与凭证绑定
- 候选源绑定需提交严格匹配的元组，仅批准通过的绑定方可生效。
- 视觉凭据必须提供真实捕获的图像文件，禁止仅使用“人工已确认”等口头声明替代真实证据。

## 8. 切换（Cutover）前置要求与运行边界
- 切换必须满足：已验证的真实角色、V01..V09 实际证据链与原生检查证明。当前状态为未执行，相关工具状态置为 false。
- 仅限 CLI 任务，不对应桌面端角色；禁止运行自动化或生产执行命令。
- 成本模型未知，禁止编造降本数据；禁止猜测时间戳或硬编码宿主绝对路径。
